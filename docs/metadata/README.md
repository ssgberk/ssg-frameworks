# Generator metadata

`generators.json` is the machine-readable index of every static site generator benchmarked in this repo. Read it directly from GitHub. It is generated by `tools/build_index.py` from each `<Lang>/<name>/generator.json` plus fields derived from the dockerfile, lockfiles and `benchmark_config.json`. CI (`.github/workflows/metadata.yml`) fails if it is stale. The design is in `docs/specs/004-generator-metadata/`.

## Raw URLs

| What | URL |
|---|---|
| Index | `https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/generators.json` |
| Index schema | `https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/schema/generators.schema.json` |
| `generator.json` schema | `https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/schema/generator.schema.json` |
| One generator | `https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/<Lang>/<name>/generator.json` |

To pin a snapshot, replace `master` with a commit SHA. `raw.githubusercontent.com` caches responses for about 5 minutes.

## Top level

| Field | Type | Meaning |
|---|---|---|
| `schemaVersion` | string (semver) | Version of this format; currently `1.0.0` |
| `generatedFrom` | string or null | Commit the index was generated from, normally the parent of the commit that contains it |
| `source` | URL | `https://github.com/ssgberk/ssg-frameworks` |
| `generators` | array | Benchmarked generators, sorted by `id` |
| `proposed` | array | Generators not in the repo yet, sorted by `id` |

## `generators[]` fields

C = curated in `generator.json`; D = derived by the build script.

| Field | Src | Type | Meaning |
|---|---|---|---|
| `id` | C | string | Directory name, equal to `benchmark_config.json` `framework` and to the toolset test name |
| `path` | D | string | `<Lang>/<name>` |
| `version` | D | string | Pinned generator version (dockerfile `ARG`, `package-lock.json`, `Gemfile.lock`, `composer.lock` or `requirements.txt`), without a leading `v` |
| `name` | C | string | Human-readable name |
| `description` | C | string | One sentence |
| `homepage` | C | URL | Project homepage |
| `repository` | C | URL | Upstream source repository |
| `license` | C | string | SPDX expression of the upstream project |
| `language` | C | string | Implementation language |
| `runtime` | C | string | Runtime in the benchmark image, e.g. `Node.js 24.21.0`; checked against the dockerfile ARGs |
| `templateEngines` | C | string[] | Template engine(s) this benchmark setup uses |
| `contentFormats` | C | string[] | Content formats supported natively or through official first-party plugins |
| `category` | C | enum | `blog`, `docs`, `framework` or `general` |
| `firstRelease` | C, optional | integer | Year of the first public release, only when verified |
| `maintained` | C | boolean | Not archived, and active upstream in the last 12 months |
| `versionFrom` | C, optional | object | `{source, name}` override for version extraction |
| `benchmark.status` | C | enum | `active`, `wip` or `removed` |
| `benchmark.displayName` | D | string | `tests[0].default.display_name` |
| `benchmark.versus` | D | string | `tests[0].default.versus` |
| `benchmark.contentType` | D | enum | Front matter style: `3minus`, `3plus`, `2dot` or `none` |
| `benchmark.contentFolder` | D | string | Where `build.sh` writes the posts |
| `benchmark.buildCommand` | D | string | The command that is timed |
| `benchmark.outputFolder` | D | string | Build output directory |
| `benchmark.outputGlob` | D | string | Glob, relative to `outputFolder`, that matches exactly one file per post |
| `benchmark.cacheFolders` | D | string[] | Folders wiped before every timed run |
| `links.issue` | C, optional | URL | Issue that tracked adding the generator |
| `notes` | C, optional | string | Caveats and the sources of the less obvious facts |
| `files.dockerfile`, `files.benchmarkConfig`, `files.readme`, `files.generatorJson` | D | URL | Raw URLs at `master` |

## `proposed[]` fields

| Field | Type | Meaning |
|---|---|---|
| `id` | string | Intended directory name |
| `name` | string | Human-readable name |
| `language` | string | Implementation language |
| `repository` | URL | Upstream repository |
| `status` | enum | `proposed` (has a `new-generator` issue) or `planned` (listed in a spec) |
| `issue` | URL, optional | The `new-generator` issue |
| `spec` | string, optional | Repo-relative path of the spec that plans it |
| `notes` | string, optional | Caveats |

## Versioning and stability

`schemaVersion` follows semver. The index and `generator.json` share one version.

- **Patch:** wording and description changes only.
- **Minor:** additive changes, such as a new optional field, a new derived field or a new enum value.
- **Major:** a removed or renamed field, a changed type, an optional field becoming required, or a removed enum value. Every major bump is described in `CHANGELOG.md` with a migration note.

Rules for consumers:

- Check that the major version is `1`.
- Ignore fields you do not know.
- Tolerate unknown enum values.
- If you validate strictly (the schemas use `additionalProperties: false`), use the schema from the same ref as the index.

## Examples

With curl and jq:

```bash
curl -fsSL https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/generators.json \
  | jq -r '.generators[] | select(.benchmark.status == "active") | [.id, .version, .language, .license] | @tsv'
```

With JavaScript (browser, Deno or Node 18+):

```js
const url = "https://raw.githubusercontent.com/ssgberk/ssg-frameworks/master/generators.json";
const index = await (await fetch(url)).json();
if (!index.schemaVersion.startsWith("1.")) throw new Error(`unsupported schema ${index.schemaVersion}`);
for (const g of index.generators) console.log(`${g.name} ${g.version} (${g.language}) ${g.homepage}`);
```

## Maintaining

- **Add or update a generator:** write `<Lang>/<name>/generator.json`, then run `python3 tools/build_index.py`. Never hand-edit `generators.json`.
- **Check before you push:** `python3 tools/build_index.py --check` (stdlib only) and `python3 -m pytest tests/metadata`.
- **The Claude Code agent `.claude/agents/generator-docs.md`** automates this, including researching the facts and moving entries out of `tools/proposed.json`.
