# Marmite

Marmite 0.4.2 on Ubuntu 24.04, benchmarked by SSGBerk. `build.sh` generates the posts into `src/content` (YAML front matter, content type `3minus`, files named `YYYY-MM-DD-NNN.md`), then times `build_command` (`marmite . site`). Each post renders to `site/post-NN-<title words>.html` (Marmite derives the slug from the title), so `output_glob` is `post-*.html` and the verification step checks that count equals the requested number of files. Run it with `./ssgberk --test marmite -nf 10` from the toolset repository.

Deviations: the version is the latest stable on 2026-10-08 (0.4.2). Marmite publishes Linux release binaries for x86_64 only, so the dockerfile downloads the pinned `x86_64-unknown-linux-gnu` tarball on amd64 and compiles the same version from crates.io (`cargo install marmite --locked`) in a build stage on arm64; the final image is the same Ubuntu base with only the binary copied in. The timed build is offline and writes no caches (`cache_folders` is empty).

Configuration (`src/marmite.yaml`): search, JSON feeds, sitemap, `urls.json`, Markdown source publishing, table of contents, related content, next/previous links, the dev toolbar, internal link checks and gallery thumbnails are off, and pagination is set to 100000. `src/templates` replaces the theme with four minimal templates (`base.html`, `content.html`, `list.html`, `group.html`): a post page shows only its own post and the index lists every post. What Marmite cannot disable: the tag, author, archive, stream, series, language and pages listing pages (rendered with the minimal group/list templates), the per-group RSS feeds, `404.html`, `robots.txt`, `marmite.json` and its stock static files in `site/static`. The author and tag pages are generated from the front matter of every post and are part of the timed build. `assets/ssgberk.css` and `ssgberk.png` live in `src/static/assets` and are copied to `site/assets/` by `file_mapping` so the `/assets/ssgberk.png` image references in the generated posts resolve.
