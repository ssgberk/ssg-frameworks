# Lektor

Lektor 3.3.14 (Jinja2 templates, minimal models and templates in `src`) on Ubuntu 24.04, benchmarked by SSGBerk. Lektor needs one `contents.lr` per page rather than markdown files, so `build.sh` generates the posts as plain markdown into `src/posts` and the timed `build_command` converts them in one bash pass (single `mkdir`, then a builtin `read`/`printf` loop, no per-post process) into `content/posts/<name>/contents.lr` (`_model: post`, `title`, `body`) before running `lektor build -O _site`. The conversion is part of the timed build, as the `SUMMARY.md` listing is for mdBook. Each post must render to `_site/posts/*/index.html`; the verification step checks the count equals the requested number of files.

`requirements.txt` is the full `pip freeze` taken inside the built image after `pip install Lektor==3.3.14`. The `posts` model lists children on the home page without pagination, and the post template renders only its own post. Build state is written to `.lektor-cache` (listed in `cache_folders`, outside `_site`). Run it with `./ssgberk --test lektor -nf 10` from the toolset repository.
