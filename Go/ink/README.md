# Ink

Ink (InkProject/ink) built from upstream commit f9aeb2b15e860440d85c1370ac408f561598567e (2026-06-08), recorded as version `nightly-f9aeb2b`, on Ubuntu 24.04, benchmarked by SSGBerk. `build.sh` generates the posts into `src/content/post`, then times `build_command`, which runs `ink build`; each post must render to `public/post/*/index.html` (the verification step checks the count equals the requested number of files). Run it with `./ssgberk --test ink -nf 10` from the toolset repository.

Deviations: Ink has no versioned releases (only a rolling `nightly` tag), so the dockerfile compiles the pinned commit in a `golang:1.25-bookworm` builder stage and copies the static binary into the runtime image. Ink splits a post at the first `---`, so it cannot read a file that starts with the canonical `---` fence, and it parses dates as `YYYY-MM-DD HH:MM:SS`. The timed `build_command` therefore runs `src/convert.awk` once over all posts (one awk process, no per-post forks) to copy them into `source/post` without the leading fence and with the date rewritten; that copy is part of the timed build and `source/post` is listed in `cache_folders`. The theme in `src/theme` is minimal (one post template, one index template, no scripts or hosted assets); `site.limit` is set high so the index lists every post, and `site.link` gives posts the URL `post/<name>/index.html`. Ink still writes `index.json`, `archive.html`, `tag.html` and tag pages; RSS and sitemap are off because `site.url` is empty. License of Ink: CC BY-NC 4.0.
