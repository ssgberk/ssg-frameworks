# Plenti

Plenti 0.7.25 (plentico/plenti, tag `v0.7.25`) on Ubuntu 24.04, benchmarked by SSGBerk. `build.sh` generates the posts into `src/md/post`, then times `build_command`, which converts them to JSON and runs `plenti build`; each post must render to `public/post/*/index.html` (the verification step checks the count equals the requested number of files). Run it with `./ssgberk --test plenti -nf 10` from the toolset repository.

Deviations: Plenti reads JSON content (`content/<type>/*.json`) and has no markdown support. The timed `build_command` first runs `src/convert.awk` once over all posts (one awk process, no per-post forks) to write `content/post/<name>.json` (title, date, summary, author, tags and the raw markdown body); that conversion is part of the timed build and `content/post` is listed in `cache_folders`. The markdown body is rendered to HTML on the Svelte side: `src/layouts/content/post.svelte` calls `marked` 18.1.0 (MIT) and emits the result with `{@html}`. Plenti's server-side renderer only resolves imports of `.svelte` files, so `marked`'s ESM build is vendored as the module script of `src/layouts/scripts/markdown.svelte` (its `export {...}` line is replaced by one `renderMarkdown` export, and the identifiers `$` and `$e` are renamed because Svelte reserves the `$` prefix). Plenti collapses whitespace runs in content to one space, which would flatten nested lists, so `convert.awk` writes runs of two or more spaces as `\u0020` JSON escapes. Plenti publishes release binaries for linux amd64 only, so the dockerfile compiles the pinned tag in a `golang:1.25-bookworm` builder stage (cgo with the bundled V8 of v8go, available for amd64 and arm64). Plenti copies its core `node_modules` into the project on every build, so `node_modules` is also in `cache_folders`. The layouts omit Plenti's client-side router script, so pages are plain static HTML. Plenti still writes an SPA bundle and per-page JSON props under `public/spa`.
