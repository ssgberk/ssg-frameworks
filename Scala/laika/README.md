# Laika

Laika 1.3.2 (`laika-io`, Scala 3.3.8) on a Temurin 21 JRE, benchmarked by SSGBerk. A multi-stage image: the builder stage (`eclipse-temurin:21-jdk-noble` plus scala-cli 1.18.0) compiles `src/Main.scala` once, untimed, into the fat jar `laika-site.jar`; the runtime stage carries the JRE, the jar, the site skeleton and the benchmark skeleton, so the timed build resolves no dependencies and touches no network. `build.sh` generates the posts into `site/posts/` (`3minus` front matter), then times `java -Xmx4g -jar /opt/laika/laika-site.jar site public`, JVM start included, as a real run of a Laika program would be; each post must render to `public/posts/*.html`.

Laika is a library, so the site is a small program: `Transformer.from(Markdown).to(HTML).using(GitHubFlavor, SyntaxHighlighting, ...).parallel[IO]`, one process for the whole tree. It runs without the Helium theme (`Theme.empty`), so `site/default.template.html` is the only chrome and a post page renders only its post. `site/index.md` uses `site/index.template.html` and the `@:postList` template directive (defined in `Main.scala`) to list every post, newest first.

Laika reads HOCON `{% ... %}` headers only, not YAML `---` front matter. `Main.scala` adds a small extension bundle (`YamlFrontMatter`, a `ConfigProvider`) that rewrites the flat YAML header into HOCON in memory and passes it to Laika's own config parser, so the posts are read unchanged and there is no pre-processing pass or per-post process. Laika writes no cache, so `cache_folders` is empty. Run it with `./ssgberk --test laika -nf 10` from the toolset repository.
