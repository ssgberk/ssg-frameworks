# Nuxt Content

Nuxt 4.5.2 with Nuxt Content 3.16.1 on Ubuntu 24.04 with Node 24.21.0, benchmarked by SSGBerk. `build.sh` generates the posts into `content/posts` (Markdown with `title`/`date` front matter, one `posts` collection over `posts/*.md` in `content.config.ts`), then times `npx nuxt generate`; each post must render to `.output/public/posts/*/index.html` (the verification step checks the count equals the requested number of files; `index.html`, `200.html` and `404.html` sit outside the glob). The site is one page component for the index (`app/pages/index.vue`, lists every post) and one catch-all post page (`app/pages/posts/[...slug].vue`, title + content only). Dependencies are installed with `npm ci` from the committed `package-lock.json`. Nuxt Content's SQLite database uses Node's built-in `node:sqlite` (`content.experimental.sqliteConnector: 'native'`), so no native module is built. Telemetry is disabled with `NUXT_TELEMETRY_DISABLED=1`. `cache_folders` clears `.nuxt`, `.output`, `.data`, `node_modules/.cache` and `node_modules/.vite` between timed runs so every run is cold. Run it with `./ssgberk --test nuxt-content -nf 10` from the toolset repository.

Timed command uses the realistic invocation (`npx nuxt …`), which includes ~0.1–0.4 s wrapper startup.

Deviations: Nuxt is an application framework; the content module makes it a Markdown site generator. The timed build includes Nuxt's Vite client and Nitro server bundling and the content database build; this is inherent to the generator and allowed. `vue` and `vue-router` are pinned explicitly (peer requirements of Nuxt).
