# Nextra

Nextra 4.6.1 on Next.js 16.3.8 (App Router, `output: 'export'`) with Node 24.21.0 on Ubuntu 24.04, benchmarked by SSGBerk. `build.sh` generates the posts into `content/posts` (the Nextra content directory, `3minus` front matter, `.md`), then times `npx next build`; each post must render to `out/posts/*/index.html` (the verification step checks the count equals the requested number of files). The site is a bare root layout, a catch-all page (`app/[...mdxPath]/page.jsx`) that renders one post through Nextra's `importPage` and an MDX wrapper showing only the title and body, and one index (`app/page.jsx`) listing every post. No Nextra theme is used, so there is no sidebar, navbar, search or table of contents. Dependencies are installed with `npm ci` from the committed `package-lock.json`; `cache_folders` clears `.next` and `node_modules/.cache` between timed runs; telemetry is disabled with `NEXT_TELEMETRY_DISABLED=1`. Run it with `./ssgberk --test nextra -nf 10` from the toolset repository.

Deviations: Nextra search is off (`search: false`; pagefind is only a separate postbuild step and is not run). The index lists post slugs, not titles. `src/public/assets/` holds the byte-identical reference `ssgberk.css`/`ssgberk.png` (force-added because the repo ignores `public/`). Timed command is the realistic `npx next build`.
