# Lustre SSG

lustre_ssg 0.11.0 (Lustre 5.7.1, Gleam 1.19.1 on Erlang/OTP 29, official `ghcr.io/gleam-lang/gleam:v1.19.1-erlang-slim` image, amd64 and arm64), benchmarked by SSGBerk. `build.sh` generates the posts into `content/posts` (`3minus` front matter), then times `gleam run -m build --no-print-progress`; each post must render to `public/posts/*.html` (the verification step checks the count equals the requested number of files).

`src/src/build.gleam` is the whole site: it reads the posts at build time, parses the YAML front matter itself (lustre_ssg has no front matter support), renders the Markdown body with `mork` (CommonMark plus GFM tables), lays every page out with Lustre elements, and hands the routes to `lustre_ssg` (`add_dynamic_route` for posts, static routes for the index and the 404 page, `add_static_dir` for the two reference assets). lustre_ssg ships only a Djot renderer, hence the separate Markdown package.

Dependencies are fetched and the project is compiled while the image is built (`gleam deps download && gleam build`), so the timed command runs offline. `gleam run` still performs its incremental compile check against `build/` (a no-op, a few hundred milliseconds), which is part of the timed command. `gleam_stdlib` is pinned below 0.68 because lustre_ssg 0.11.0 requires `jot` 4.0.0, which calls `result.then` (removed in stdlib 0.68). The slim image has no CA certificates and Gleam's Hex client fails with "builder error" without them, so the dockerfile installs `ca-certificates`. Run it with `./ssgberk --test lustre-ssg -nf 10` from the toolset repository.
